Tasks or outputs before the start cycle point can now immediately return as
succeeded or completed when queried by a `workflow_state` xtrigger or the `cylc
workflow-state` command. This behaviour is controlled with the
`accept_pre_start_tasks` argument and the `--accept-pre-start-tasks` option
respectively, and can be used to prevent warm-started workflows getting stuck
waiting for earlier tasks that will never exist.
